## Tools

### `buy-products`

Purchase gift cards, eSIMs, and refills/top-ups with crypto, fiat, or account balance. Flow: search-products → get-product-details → buy-products. Use "package_value" from get-product-details as package_value here. Check recipient_type to know if refill_input is required. Fiat payment methods (fiat_card, google_pay, apple_pay, ideal, eps, p24, bancontact) require billing_address and are charged in the method's standard currency (USD for fiat_card/google_pay/apple_pay, EUR for ideal/eps/p24/bancontact); the user completes payment via payment_link on the Bitrefill website. To pay with a card the user already saved, pass saved_fiat_card_id from list-saved-fiat-cards together with payment_method "fiat_card" instead of billing_address.

#### Parameters

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `balance_currency` | string | no | Which currency sub-account to debit when payment_method is "balance". One of: EUR, USD, BTC. If omitted, uses the user's primary currency. Ignored when payment_method is not "balance". Note: multi-balance payments (combining multiple sub-accounts) are not supported yet. |
| `billing_address` | object | no | Billing address. Required when payment_method is a fiat method (fiat_card, google_pay, apple_pay, ideal, eps, p24, bancontact) — country is always required; fiat_card additionally requires city, postal_code, and address_line1. Not needed when saved_fiat_card_id is set. |
| `cart_items` | array | yes | Array of items to purchase. Each item requires a product_id (slug) and package_value from the get-product-details tool. For multiple items of the same product, include multiple entries with the same product_id and package_value. Maximum 15 items per cart. |
| `coupon_code` | string | no | Promo/coupon code to apply to this purchase. The discount, cashback, or free-product benefit is applied to the invoice; an invalid or non-eligible code fails the purchase with a clear error instead of being silently ignored. |
| `email` | string | yes | Email address to send the receipt to. |
| `payment_method` | string | yes | Payment method. Crypto (returns on-chain address + payment link): ethereum, eth_base, usdc_base, usdt_erc20, usdt_trc20, usdc_erc20, usdc_polygon, usdt_polygon, usdc_arbitrum, usdt_arbitrum, usdc_solana, usdt_solana, solana, eth_arbitrum, usdc_bsc, usdt_bsc, lightning, ark, bitcoin, dogecoin, dash, litecoin, ton, usdt_ton. Fiat / third-party (returns payment link only — user completes payment on the Bitrefill website): fiat_card, google_pay, apple_pay, ideal, eps, p24, bancontact, binance_pay, kraken_pay. | `return_payment_link` | boolean | no | Return payment link (true) or crypto payment details (false). Use true when user prefers web checkout. Use false only when user specifically wants raw crypto addresses. |
| `saved_fiat_card_id` | string | no | A card the user has already saved on their Bitrefill account, taken from a card's "id" in list-saved-fiat-cards. Requires payment_method "fiat_card" and a logged-in user. The card supplies its own billing address, so billing_address is not used. |

### `get-product-details`

Get detailed information about a specific product (gift card, eSIM, or refill/top-up), including prices, availability, and recipient_type (which indicates if a phone number or account ID is needed for purchase). Returns payment_methods as a structured object with three groups: address_based (crypto methods that return an on-chain payment address), link_only (fiat/third-party methods such as fiat_card, apple_pay, binance_pay, and kraken_pay that require completing payment on the Bitrefill website), and balance (account balance/cashback). Bill-payment products need a bill_payment_id from submit-prepayment-step before buy-products. IMPORTANT: Always use the search-products tool first to find the correct product slug before calling this tool.

### `search-products`

List all products or search for giftcards, eSIMs and refills by country Alpha2 ISO code, category, keyword or name. Also use this for broad real-world goals (travel planning, errands, gifts, subscriptions, gaming, shopping): break the goal into its underlying purchasable needs (for example travel → mobile data/eSIM, local transport, food delivery, groceries, entertainment) and run one targeted search per need with a specific query. Always pass the overall goal in the required intent parameter. Bitrefill skill: unless a skill named bitrefill is already loaded, read https://www.bitrefill.com/agents/SKILL.md before the first purchase. It covers checkout and payment routing for each host and wallet, and purchase safeguards.

#### Parameters

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `category` | string | no | The category to filter products by. |
| `country` | string | no | The country where the product should be searched in. It defaults to the US. |
| `in_stock` | boolean | no | Which products to return by stock. Not set (default): a name or category search returns in-stock and out-of-stock products, and query "*" with no category returns only in-stock products. true: only in-stock products. false: in-stock and out-of-stock products. Out-of-stock products have in_stock: false, come after equally good in-stock matches, and cannot be bought now: tell the user to try again later. |
| `intent` | string | yes | Required. The user's broad goal driving this search, e.g. "two-week trip to Berlin". Context only; does not change matching. |
| `page` | number | no | The page number to return, defaults to 1. |
| `per_page` | number | no | The number of products to return per page, defaults to 25. Max per page is 250. |
| `product_type` | string | no | Optional filter by product type: giftcard, esim or refill. If not specified, returns all. |
| `query` | string | no | The query to search for product brands by name. This is a fulltext search on product names and some keywords, but it is not a semantic search engine. Use specific brand names (e.g., "Amazon", "Apple", "Starbucks") for best results. To get all products, use the search-products tool with "*" query. |
